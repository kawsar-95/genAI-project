# AI-Driven Quality Engineering: Project Setup, Knowledge Graphs & Change Impact Analysis

> **Executive Overview**  
> Modern Software Quality Assurance (SQA) is transitioning from passive black-box testing to proactive, AI-assisted **White-Box Quality Engineering**. By integrating deterministic AST-based Knowledge Graphs (**Graphify**) with intelligent context management (**Claude Code**) and impact analysis skills (**Blast Radius**), quality engineers can map full-stack microservice dependencies, predict regression risks, and automate bug analysis with high precision and minimal token consumption.

## 1. System Architecture & Project Setup (DMoney Platform)

Understanding the complete system requires setting up a realistic full-stack fintech platform (**DMoney**). The environment establishes a baseline for multi-service testing and database verification.

```
+-----------------------------------------------------------------------+
|                            DMoney Workspace                           |
|                                                                       |
|  +---------------------------+       +-----------------------------+  |
|  |     Frontend App          |       |     Backend API             |  |
|  |   (Next.js / React)       | <---> |  (Node.js / Express API)    |  |
|  |   Port: 3000              |       |  Stripe & Email Settings    |  |
|  +---------------------------+       +-----------------------------+  |
|                \                            /                         |
|                 v                          v                          |
|  +-----------------------------------------------------------------+  |
|  |               MySQL Database Engine & Client                     |  |
|  |   Client: DBeaver (`allowPublicKeyRetrieval=true`)               |  |
|  |   Tables: Users, Transactions, Balance, System Seed Data        |  |
|  +-----------------------------------------------------------------+  |
+-----------------------------------------------------------------------+
```

### Key Setup Steps & Environmental Configuration
1. **Node.js Environment**:
   - Requires Node.js **LTS (Long Term Support)** versions (e.g., Node.js v24 / v26 LTS) to maintain workspace stability across build and dev pipelines (`npm run dev`).
2. **VS Code & Workspace Sanitation**:
   - Workspace paths must **never contain spaces** or special characters to prevent CLI and path resolution errors in automated scripts.
   - Installation flag: Ensure `Open with Code` context menu options are enabled in Windows Registry for smooth CLI invocation.
3. **Database Client & Troubleshooting**:
   - **DBeaver** is utilized as a multi-database visual client supporting MySQL, PostgreSQL, Amazon RDS, and SSH tunnels.
   - **Connection Fix**: Enable `allowPublicKeyRetrieval=true` under DBeaver's *Advanced Driver Properties* when encountering driver authentication handshake locks.
4. **Environment Variables (`.env`)**:
   - Standardized configuration for app credentials, temporary email passwords, and Stripe payment secret keys.

## 2. AI Tooling & Knowledge Graph Integration (Graphify)

Traditional AI coding assistants treat codebases as isolated files, causing token exhaustion and context truncation when analyzing complex microservice architectures. **Graphify** solves this by converting code repositories into queryable, multimodal Knowledge Graphs.

```
                                  +-----------------------+
                                  |   Project Codebase    |
                                  | (Frontend & Backend)  |
                                  +-----------------------+
                                              |
                                              v
                              +-------------------------------+
                              |    Tree-sitter AST Parser     |
                              |  (Local, Deterministic, 0 Token|
                              +-------------------------------+
                                              |
                                              v
                              +-------------------------------+
                              |   Leiden Community Detection  |
                              |  & Subsystem Node Mapping     |
                              +-------------------------------+
                                              |
      +---------------------------------------+---------------------------------------+
      |                                       |                                       |
      v                                       v                                       v
+------------------------+          +------------------------+          +------------------------+
|       graph.json       |          |       graph.html       |          |    GRAPH_REPORT.md     |
| (GraphRAG schema for   |          | (Interactive visual    |          | (God Nodes & Subsystem |
|  AI instant lookups)   |          |  browser map)          |          |  pathway breakdown)    |
+------------------------+          +------------------------+          +------------------------+
```

### Installation & Initialization Pipeline
```bash
# 1. Install fast Python package manager (UV)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# 2. Install Graphify globally
uv tool install graphify

# 3. Initialize Graphify skill inside project workspace
graphify install

# 4. Generate Knowledge Graph inside Claude Code / AI Assistant
/graphify .
```

### Graphify Output Artifacts (`graphify_out/`)
- **`graph.json`**: The core persistent memory layer. Acts as a GraphRAG schema that Claude Code reads to resolve cross-file method calls and dependencies instantaneously without grepping.
- **`graph.html`**: An interactive web interface visualizing system nodes, edges, and cluster communities.
- **`GRAPH_REPORT.md`**: Human-readable summary highlighting **God Nodes** (critical hub files/functions that manage heavy system traffic, such as `LeftMenu.tsx` or balance calculation functions).

## 3. Comparison: Graphify vs. Blast Radius

In AI-driven quality engineering, system mapping (**Graphify**) and change impact analysis (**Blast Radius**) serve complementary, synergistic roles.

| Metric / Dimension | Graphify (Knowledge Graph) | Blast Radius (Impact Analysis Skill) |
| :--- | :--- | :--- |
| **Primary Focus** | Complete architectural topology & call-graph mapping | Target change impact analysis ("What breaks if I change X?") |
| **Data Structure** | Persistent Knowledge Graph (`graph.json` with nodes & edges) | Temporal dependency matrix & Git commit symbol lookup |
| **Scope** | Global system view across frontend, backend, and docs | Delta analysis between commits, pull requests, or code edits |
| **Execution Trigger**| Manual `/graphify .` or Git Hooks (`post-commit`) | Executed during code reviews and pre-commit SQA checks |
| **Role in SQA** | Provides full structural context to the AI Assistant | Pinpoints regression risks and highlights affected test suites |

> **Synergy**: Blast Radius runs **on top of** Graphify's pre-computed `graph.json`. By querying the Knowledge Graph, Blast Radius evaluates change impacts across microservices instantly without scanning raw source files repeatedly.

## 4. Workspace Architecture & SQA Best Practices

To maintain clean separation between developer code and SQA test automation workflows, teams adopt structured workspace rules and AI guardrails.

```
dmoney-workspace/
├── .claude/
│   ├── skills/                  <-- Custom QA Skills
│   │   ├── analyze-requirements.md
│   │   ├── blast-radius.md
│   │   ├── test-design.md
│   │   └── test-charter.md
│   └── settings.json            <-- Pre-hooks & Security Guardrails
├── CLAUDE.md                    <-- Global Workspace Blueprint
├── graphify_out/                <-- Generated System Knowledge Graph
│   ├── graph.json
│   ├── graph.html
│   └── GRAPH_REPORT.md
├── dmoney-backend/
│   └── CLAUDE.md                <-- Service-Specific SQA Instructions
└── dmoney-frontend/
    └── CLAUDE.md                <-- Service-Specific SQA Instructions
```

### 1. Workspace vs. Sub-Project Context (`CLAUDE.md`)
- **Root `CLAUDE.md`**: Outlines overall workspace relationships, microservice orchestration, shared database endpoints, and SQA directory conventions (`.artifacts/`).
- **Sub-project `CLAUDE.md`**: Contains isolated build commands, linter rules, and testing scripts for individual services (e.g., frontend vs. backend).

### 2. Guardrails & Security Hooks (`settings.json`)
- **Pre-execution Hooks**: Intercept commands before sending context to LLMs, blocking sensitive data leaks (API secret keys, `.env` credentials, database connection strings).
- **Quality Enforcers**: Enforce structural validation checks before committing changes to Git repositories.

### 3. Automated Git Hook Integration
Graphify binds to Git workflows to maintain live system maps:
```bash
# Automatically updates graph.json on commit or checkout
graphify hook install
```

## 5. Modern Quality Engineering Principles

1. **Shift to White-Box SQA**: AI agents enable SQA engineers to inspect underlying source code, database schemas, and microservice call paths rather than relying solely on UI/API black-box checks.
2. **Deterministic Parsing First**: Utilizing local AST parsers (tree-sitter) eliminates token costs and protects proprietary code privacy.
3. **Token-Efficient Reasoning**: Leveraging persistent Knowledge Graphs (`graph.json`) reduces context window usage by up to 80-90% during bug investigation and test design.
4. **Automated Defect & Regression Tracking**: Linking AI assistants with Git, Jira, and test reporting tools accelerates bug detection, impact analysis, and resolution verification.
