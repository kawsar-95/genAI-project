# Mastering AI Agents for Semantic Bug Discovery & Automation

## Executive Summary

Modern AI-driven software quality assurance (QA) is shifting from basic LLM code-reading to **autonomous, agentic white-box and black-box bug discovery**. Traditional LLMs struggle with semantic bug discovery when relying solely on generic text search (`grep`/`glob`) or raw file ingestion—often burning token context limits, hallucinating non-existent flaws, or missing subtle cross-function regressions.

This guide details the end-to-end framework for harnessing AI coding agents (such as Claude Code) using specialized tools, knowledge graphs, semantic LSP tools, browser automation, and Model Context Protocol (MCP) servers.

---

## 1. Architectural Tooling Stack

To achieve deep, high-confidence bug discovery, an AI agent must combine white-box structural code intelligence with black-box behavioral verification:

```
                  +-----------------------------------+
                  |         AI Agent (e.g. Claude)     |
                  +-----------------+-----------------+
                                    |
            +-----------------------+-----------------------+
            |                                               |
  [White-Box Intelligence]                        [Black-Box Execution]
  +-----------------------+                       +-----------------------+
  | Serena (LSP/AST)      |                       | Agent Browser (CLI)   |
  | Graphify (Code Graph) |                       | Postman MCP (API)     |
  | Blast Radius Analysis |                       | DB MCP (State)        |
  +-----------------------+                       +-----------------------+
            |                                               |
            +-----------------------+-----------------------+
                                    |
                        [Multi-Agent Verification]
                        +-----------------------+
                        | Codex MCP / Reviewer  |
                        +-----------------------+
                                    |
                        [Lifecycle Tracking]
                        +-----------------------+
                        | Jira MCP Ticket Auto  |
                        +-----------------------+
```

### White-Box Tools (Code & Domain Awareness)
1. **Serena (LSP/AST Semantic Engine)**
   - **Role:** Provides language-server-protocol (LSP) precision for single-hop and multi-hop code symbol traversal (definition tracing, callers/callees, type resolution).
   - **Why it matters:** Replaces crude `grep` matching with exact function-to-function call chains, exposing internal regression dependencies.
2. **Graphify (Codebase & Domain Knowledge Graph)**
   - **Role:** Generates a persistent, queryable knowledge graph (`.graphify/`) mapping files, symbols, modules, and business logic (from READMEs, BRDs, or `CLAUDE.md`).
   - **Token Efficiency:** Reduces token consumption by up to 70% by providing high-level graph summaries (`GRAPH_REPORT.md`) instead of reading raw files repeatedly.
3. **Blast Radius Analysis**
   - **Role:** Analyzes downstream code impact when specific core functions or contracts change, pinpointing which modules and tests are at risk of breaking.

### Black-Box Tools (Behavioral & Interface Verification)
4. **Agent Browser (CLI UI Automation)**
   - **Role:** Runs headless/console-mode UI navigation. Uses compact DOM snapshots and semantic element tags (`@e1`, `@e2`) rather than verbose HTML trees.
   - **Why it matters:** Enables closed-loop UI exploratory testing while saving ~90%+ context window compared to standard Playwright dumps.
5. **Postman MCP & Confluence Markdown Dumps**
   - **Role:** Provides live, updated API collection schemas via Postman MCP and structured markdown context for microservices, keeping business context fresh without hallucinating parameters.

## 2. Deterministic Workflow Control via Pre-Hooks

AI agents can occasionally overlook specialized tools and fall back on basic file reads. To prevent drift, engineers implement **Pre-Hooks** in environment configurations (e.g. `.claude/settings.json`).

### Mechanics of Pre-Hook Enforcement
- **Trigger:** Before executing a bug-finding or test-design instruction, the environment fires a pre-hook trigger (`preHook`).
- **Action:** Runs a script (Bash/Node.js) that explicitly initializes **Serena** and loads/rebuilds the **Graphify** knowledge index.
- **Benefit:** Guarantees that every bug scan operates with full semantic code context, eliminating missed dependencies and unnecessary token waste.

## 3. The End-to-End Bug Discovery Process

```
Step 1: Domain & Code Pre-Hook
  ├── Activate Serena LSP
  └── Query Graphify Knowledge Graph & BRDs
        │
Step 2: Static Code & Impact Scan (White-Box)
  ├── Map cross-function call chains
  └── Identify edge cases & Blast Radius risks
        │
Step 3: Reproduction & Verification (Black-Box)
  ├── Attempt reproduction via Agent Browser UI (@e references)
  └── Fallback to direct API invocation via Postman MCP if UI unavailable
        │
Step 4: Adversarial Multi-Agent Audit (Optional)
  └── Codex MCP cross-checks candidate findings to filter false positives
        │
Step 5: Automated Incident Delivery
  └── Jira MCP generates structured report with steps, severity, & screenshots
```

### Bug Report Output Format
A standardized bug report generated by the agent follows a strict structure:
- **Bug ID & Title**
- **Severity & Confidence Score** (e.g., Confirmed / Highly Likely)
- **Reproduction Steps** (UI path prioritized, API fallback)
- **Expected vs. Actual Behavior**
- **Impact & Affected Modules**

## 4. Prompt Engineering & Skill File Architecture

To standardize agent behavior across project teams, custom **Skill Files** (e.g. `findbug.md`) are stored within the repository.

### Guidelines for Skill Files
- **Keep it Lean:** Max ~200 lines to avoid context bloat.
- **Mandatory Tool Rules:** Specify exact tool usage sequences (e.g., "Must use Serena and Graphify before flagging code bugs").
- **Anatomy of an Effective Prompt (The 6-Part Structure):**
  1. **Role:** (e.g., "You are a Lead QA Automation Architect")
  2. **Context:** (e.g., Project structure, seed data, DB context)
  3. **Instruction:** (e.g., "Find high/medium/low severity bugs in the Cash-In module")
  4. **Input Data:** (e.g., Test credentials, API payloads)
  5. **Constraints:** (e.g., "Do not suggest code refactor order; output structured report only")
  6. **Output Format:** (e.g., Specific markdown schema or Jira payload)

## 5. Realistic Assessment & Industry Best Practices

### The 70/30 Automation Rule
- **70% Accelerated Efficiency:** AI agents excel at repetitive regression suites, static flaw identification, API contract checks, and rapid reproduction step writing.
- **30% Critical Human QA:** Edge cases involving race conditions, architectural database deadlocks, complex auth session timeouts, and non-deterministic load bottlenecks still require human intuition and deep domain expertise.

### Key Implementation Takeaways
1. **Repository Access is Non-Negotiable:** Black-box UI testing alone gives only surface feedback. Real semantic bug discovery requires read access to the backend codebase to construct call graphs and understand state mutations.
2. **Deterministic Pre-Hooks Win Over Instructions:** Do not rely on natural language prompts alone to enforce tool usage—use `preHook` scripts.
3. **Consolidate Artifacts:** Store test outputs, bug logs, and screenshots under a dedicated `.artifacts/` folder to keep workspace state organized.
