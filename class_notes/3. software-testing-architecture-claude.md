# Comprehensive Architecture & Workflow Guide: Agentic Software Testing with Claude AI

---

## Executive Overview

Modern software development is shifting rapidly from manual test writing and simple chat assistance toward **Agentic Software Testing**. In this paradigm, AI agents (such as Claude AI / Claude Code) autonomously inspect repositories, analyze business requirements, trace code dependencies, and execute targeted white-box test suites.

This guide provides the complete architectural setup, design rules, and operational workflow based on real-world engineering practices and industry standards. It synthesizes project context from the **DMoney FinTech Application** (Node.js/Express backend + Next.js frontend) with cutting-edge agentic QA methodologies.

## 1. Core Architectural Setup & Context Engineering

### 1.1 The Context Overflow Challenge in Multi-Repo / Microservice Environments
When working with large production applications (such as a separate REST API backend and Next.js UI frontend), loading the entire codebase into a single AI context window causes **context window budget exhaustion** and leads to severe **LLM hallucinations**.

```
❌ Poor Practice: Single Root Folder for All Repos
[ DMoney WorkSpace Root ]
 └── .claude/  <-- Bloated context window; backend & frontend mixed together

-------------------------------------------------------------------------------

✅ Best Practice: Project-Specific Context Boundaries & Root Sibling Architecture
[ WorkSpace Root ]
 ├── CLAUDE.md                   <-- Root high-level architecture & service mapping
 ├── dmoney-transaction-api/
 │    └── .claude/               <-- Backend-specific memory, skills, & rules
 └── dmoney-web-ui/
      └── .claude/               <-- Frontend-specific memory, skills, & rules
```

### 1.2 Initializing Project Memory (`CLAUDE.md`)
Running `claude /init` (or `/init`) inside a repository generates a project memory file named `CLAUDE.md`. This file is automatically injected into Claude's memory every time a session starts.

#### Token Budgeting Rules for `CLAUDE.md`:
* **Target Length**: Under **150–200 lines** (absolute ceiling: 300 lines).
* **Golden Rule**: If removing a line does not cause Claude to make mistakes, **cut it**.
* **Contents**: Project orientation (1-2 lines), build/test commands, framework routes/middlewares, and mandatory architectural conventions.

## 2. Operational Modes in Agentic Workflows

Claude AI operates across four distinct permission and execution modes:

| Execution Mode | Description | Primary QA / Dev Use Case |
| :--- | :--- | :--- |
| **Plan Mode** | Read-only mode. Can read files, search codebases, analyze dependencies, but **cannot edit code**. | Requirement analysis, acceptance criteria drafting, risk evaluation, and architectural discussion. |
| **Auto Mode** *(Default)* | Autonomous file editing and command execution without asking for permission on routine tasks. | Long-running test generation, refactoring, autonomous debugging, and automated test execution. |
| **Manual Mode** | Prompts for confirmation before every file read, file edit, or CLI command execution. | High-security environments or critical infrastructure modifications. |
| **Edit Automatically** | Allows file edits without permission, but prompts before executing CLI terminal commands. | Isolated code refactoring sessions. |

## 3. Modular Skill Architecture (`.claude/skills/`)

Skills are reusable instruction modules saved under `.claude/skills/<skill-name>/SKILL.md`. Each skill should ideally remain under **200 lines** to maintain token efficiency.

```
.claude/
├── skills/
│   ├── analyze-requirement/
│   │   └── SKILL.md             <-- Extracts tabular acceptance criteria & open questions
│   └── blast-radius/
│       ├── SKILL.md             <-- Analyzes git diffs & dependency impact cascades
│       └── scripts/             <-- Helper scripts (e.g., node diff parser)
├── rules/                       <-- Domain-specific constraints
└── settings.json                <-- Pre-hooks and post-hooks configuration
```

---

### 3.1 Requirement Analysis Skill (`analyze-requirement`)
Executed **before** developer implementation starts. It parses Jira issues, GitHub tasks, or specification documents to establish testable conditions without inspecting unwritten code.

#### Key Functions:
1. **Scope Definition**: Clarifies exact functional boundaries.
2. **Tabular Acceptance Criteria**: Generates structured tables with columns:
   * `Criterion ID` | `Category` (Functional/Validation/Security) | `Source` | `Rule/Behavior`
3. **Open Questions for Stakeholders**: Highlights missing business rules before coding begins.

---

### 3.2 Blast Radius & Impact Analysis Skill (`blast-radius`)
Executed when inspecting branch changes or pull requests. It runs `git diff` against `main` and traces dependency linkages across controllers, services, middleware, and database models.

## 4. Software QA Testing Philosophy & White-Box Testing

To achieve high quality engineering, testing strategies must balance three pillars:

```
          ▲
         / \
        /   \     20% Experience-Based Testing (Exploratory / Heuristic)
       /-----\
      /       \   40% White-Box Testing (Code structure, branches, race conditions)
     /---------\
    /           \ 30–40% Black-Box Testing (API endpoints, UI validation)
   /-------------\
```

### Why QA Engineers Need Direct Codebase Access:
1. **Uncovering Hidden Edge Cases**: Black-box API testing covers at most ~50% of real failure modes.
2. **Structural Coverage**: Code inspection surfaces unhandled promises, database lock issues, edge-case conditionals, and security vulnerabilities (e.g., hash leakage).
3. **Shift-Left Quality**: QA teams write precise acceptance criteria and test charters before code freeze.

## 5. Model Context Protocol (MCP) & Ecosystem Integrations

Claude AI leverages **Model Context Protocol (MCP)** servers to seamlessly interface with external development tools:

* **Jira / GitHub MCP**: Reads user stories, fetches tickets, posts test summaries, and traces pull requests.
* **Playwright MCP**: Conducts autonomous browser exploratory testing, records failures, and auto-generates test scripts.
* **Plugin Ecosystem**: Tools like `Superpower`, `Claude MD Management`, `PR Reviewer`, and `Skill Creator` enhance workflow automation.
